# Contributing

## Getting Started

Clone the repository and follow the setup instructions in the README.

Project specific setup, test, and lint commands will be added here as the codebase is finalized. The Quality Owner is responsible for keeping these instructions up to date.

## Workflow

- Create a new branch for your work.
- Make and test your changes locally.
- Open a pull request when the work is ready.
- Do not push directly to the main branch unless the team agrees it is necessary.

## Pull Requests

Pull requests should briefly explain what changed and how it was tested.

At least one other team member should review a pull request before it is merged. Larger changes may need more discussion before approval.

## Definition of Done

Work is considered done when:

- The change works as expected.
- Relevant tests pass.
- The code has been reviewed by another team member.
- Documentation is updated when needed.
- No credentials or sensitive information are included.
- Required CI checks pass before merging.

Any missing automated testing or linting checks will be added as the project develops, with the Quality Owner responsible for keeping these requirements current.

## Contribution Norm

Each team member should complete at least one meaningful piece of accepted work each sprint.

This can include code, testing, documentation, design, or other agreed project work.

## Communication

If someone is blocked or needs help, they should post in the CS 461 Teams chat or ROB Capstone group chat.

Questions about project decisions should be brought to the team rather than left unresolved.
